# GUI 研究工作台

## 打开

在 Finder 中双击源码目录中的 `打开研究工作台.command`。工作台只监听本机，自动打开浏览器。查看与创建项目只需要 Python 3.11+；开始真实研究还需要本机已经配置好的 Node.js 与 DSH。启动器优先使用项目虚拟环境，也能直接使用本机 Python，无需先安装这个包。

使用安装后的命令也可以打开：`ari gui`。默认项目位置是 `~/work/research`；可用 `--workspace /另一个目录` 更改，用 `--port 8174 --no-open` 固定端口并只显示地址。

## 创建并开展研究

首页点击“新建课题”，输入名称和目标。目标里可以一起说明已有认识、希望探索的方向和必须遵守的约束。材料可选择文件或文件夹，也可直接填本机路径；材料供 agent 读取，研究产生的新文件放在各自工作区中。

默认预算 100000 token，同时开展 2 个探索。更细的单次预估和时间限制放在高级设置中。预算用于准入与记账，不是供应商侧的精确硬上限。

“创建课题”仅保存项目，随后“开始研究”才调用模型。页面显示运行状态和研究图。初次提出方向、运行探索、发布材料都需要时间。首轮尚无节点时，页面显示规划活动、provider/model、耗时和最近工具步骤；空图并不代表没有执行。

名称对应默认目录，也可明确填写其他新的保存目录。工作台拒绝覆盖已有目录。已有项目应通过“打开已有课题”选择。

## 运行中的交互

- **暂停**：停止后续派发，当前已经开始的调度步骤和探索可以收尾。
- **继续**：先核对原来的执行，再接续工作，重复点击不会启动第二个协调者。
- **停止**：请求终止受管作业，状态与用量在收集后更新。
- **课题设置**：调整预算、并发、只读材料和后续研究要求。正在运行的节点保留自己的上下文，新探索采用更新后的设置。
- **研究路径**：点击节点查看输入、发现、固定版本材料和未决事项；追溯上下游或沿修订跳转。
- **导出**：下载自带数据的交互式 HTML，展示导出时的状态。

原始研究目标保留；改变接下来做什么，填写“后续研究要求”。它保存为版本化研究笔记，不会改写历史节点。

关闭浏览器不会停止研究。退出工作台服务后，已经派发的作业可能继续运行；重新打开项目并“继续”会先核实原作业。模型调用可能仍有费用，未知用量继续保留占用，不会因关闭窗口归零。

已由另一个 CLI 协调器管理的课题可以查看和请求暂停；要从 GUI 接续或停止，应先退出原协调器。工作台不会强行接管另一个控制进程。

## 与独立地图的区别

`ari gui` 是创建与管理入口。`ari -p 项目 view` 和导出的 HTML 继续作为只读地图使用。工作台的控制通过固定接口调用同一份 Store 和 Runtime，没有第二套节点、预算或调度账本。

本机服务不提供任意 shell 命令或文件目录下载接口；写操作只接受工作台当前会话的同源请求。系统文件选择窗口仅在点击对应按钮后打开。
