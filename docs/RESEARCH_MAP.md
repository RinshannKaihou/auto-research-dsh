# 交互式研究路径

研究地图直接读取已有项目的 SQLite 快照。它是 v0.1 的常规查看入口，既能看研究如何分叉、交叉与汇聚，也能检查每一步交出了什么、还缺什么。

## 打开

```bash
ari -p /path/to/study view
```

仅监听 `127.0.0.1`，默认选择空闲端口并打开浏览器。使用 `--port 8173 --no-open` 固定端口、只打印地址。研究调度可以在另一个终端运行，地图每 3 秒读取持久化状态。退出地图不会暂停或终止研究。

页面更新来自数据库，不通过观看动作触发 `reconcile`。如果调度已经停止，后台结果尚未收集，页面会保留上一次入账的状态；此时运行 `ari -p /path/to/study reconcile`。

## 看一条路径

- 点节点：阅读本次目的与计划、来自哪些材料、固定版本产物、发现、适用条件、未决事项与下一步。
- 点引用：跳到来源节点。产品保留归档路径和完整版本，便于通过 CLI 查询与核对。
- 上游／下游：追踪与所选节点关联的来源或后续工作。它是引用路径，不是因果证明。
- 搜索、问题与状态筛选：缩小视野；清除筛选回到全图。
- 拖动空白画布平移，滚轮或按钮缩放，适配按钮回到可见全图。节点可用键盘聚焦并选择。

实线箭头是材料来源 → 使用者；虚线箭头是旧发现所在节点 → 后来的修订节点。二者可能连接同一对节点。没有手动编排的层级或专门的“汇聚类型”：节点同时使用多条分支的材料，就会自然画成汇聚。

## 状态不能替代科学判断

“待开展”“进行中”“已归档”来自节点状态；运行、失败、中断或待核实来自执行尝试，单独展示。已归档只是这一段工作完成交接。半成品继续标出缺口，不会被画成已验证结论；修订也不会抹除旧发现或自动撤销下游工作。

布局可以处理多起点和循环输入数据。当前固定引用协议要求来源先归档，因此研究回访通常表现为新节点再次接续旧材料；地图没有为绘图增加禁止回访的规则。

## 离线与演示

```bash
ari -p /path/to/study export
```

打开 `.research/views/research-map.html`。页面包含导出时的完整图数据，支持相同的本地浏览交互，不联网刷新。研究更新后再次导出即可。HTML 包含研究正文，适合自行保存或分享给有权查看这些材料的人。

```bash
PYTHONPATH=src python3 scripts/create_visual_demo.py --project /tmp/ari-map-demo
ari -p /tmp/ari-map-demo view
```

演示脚本通过同一存储和归档接口创建八节点理论探索示例，包含两个分支、半成品、修订和综合。它拒绝覆盖已有项目，不调用模型，不是研究效果实验。

独立地图仅提供查看。创建课题、修改预算、暂停和继续可以使用新的 [GUI 工作台](WORKBENCH.md)，也可继续使用 CLI。地图没有额外服务依赖，没有公开文件目录的 HTTP 接口。

## 重跑界面检查

```bash
node tests/visualization_graph.mjs
python -m pip install -e '.[browser-test]'
python -m playwright install chromium
PYTHONPATH=src python3 tests/browser/check_research_map.py --output-dir /tmp/ari-ui-check
```

若已有 Chromium，可用 `--browser /absolute/path/to/chromium` 指定执行文件，不必重复下载。浏览器检查创建独立临时项目和仅本机服务，验证真实点击、追溯、筛选、刷新、离线文件、循环布局及移动端；不会操作已有研究，也不调用模型。截图与检查摘要保存在指定输出目录。
