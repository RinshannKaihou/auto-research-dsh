## GUI 工作台

工作台浏览器测试使用实际 HTTP 服务、Workbench、生产调度器和本机子进程，后端替换为有延迟的确定性脚本。创建课题时没有执行记录；最新回归中点击开始后形成 1 个节点、3 次执行。暂停允许当前任务收尾，继续产生第二代协调器，停止实际中断正在运行的模拟执行；最终没有活动执行。早先版本的 3 节点/5 次执行验证同样保留了未完成节点。

## 完整流程实际检查了什么

确定性后端经过生产用 scheduler、真实 supervisor 子进程与 SQLite，完成 A → B/C → D → E：

- A 关闭时没有 findings，留下未完成草稿。
- B、C 同时运行；B 发布半成品后，D 在 C 尚未完成时先接手。
- C 读取 B 已发布的局部发现并登记修订；旧发现仍可引用。
- E 组合 C、D 的固定产物，课题仍可以没有最终答案。
- 5 个节点全部完成工作交接；协调调用与 worker 共 11 个尝试，全部计入账本。

另外用故障注入检查：领取竞争、重复提交、发布完成但未结算时崩溃、协调者部分提交后重收集、执行者仍存活时协调者退出、supervisor 被杀但 backend 仍存活、取消后残余子进程、未知费用，以及备份恢复后移走原目录再接续。

测试中修复的主要问题包括：幂等请求返回旧状态导致重复派发风险；macOS 启动器改变命令路径导致进程身份误判；畸形 usage 卡住收集；恢复后使用旧绝对路径；协调者失败后无法重试；并发导出视图使用同一临时文件。

## 真实 DSH 验证的范围

实测使用本机已有 DSH 0.1.2-alpha.2 配置，未修改用户 profile。

- coordinator 成功返回符合核心 schema 的提案，用量 801 tokens。
- 第一次 worker 写出进度和半成品，但最终 JSON 解析失败。该次旧日志没有记录费用，保留为未知。
- 加入 `submit_result` 工具后，worker 成功提交，留下 progress.json 和 partial 产品，用量 4860 tokens。

成功输出还经当前 schema 校验。没有将 3 次调用全部描述为成功，也没有把失败调用记作免费。

整条研究图流程使用的是确定性后端；真实模型验证覆盖接口、工作目录与交接，不构成长程真实研究效果证据。v0.1 是否减少研究漂移或改善理论发现，仍需后续真实试用。

## 当前边界

1. DSH 工具沙箱目前针对 macOS Seatbelt；不在其他平台自动降级为无限制执行。
2. DSH SDK 会话不复连。受管进程还活着时继续收集；已结束时，新会话从保存的工作接手。
3. token 预算是预占和记账，不是供应商的精确硬上限。单次超额照实记录，未知保留占用。
4. 备份不复制外部数据集、源 Git 仓库或模型凭据。那些依赖仍需可用。
5. 不支持运行中节点互相引用可变文件、执行者自建常驻后台服务、多机调度或自动科学正确性判定。

这些边界也写进了使用文档；没有用固定实验脚本的通过替代真实后端控制验证。
